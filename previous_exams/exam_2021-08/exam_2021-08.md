# Question 2: Interpolating and fitting (5p)

We have made an experiment and data has been collected in a simple text file `measurements.txt`.
The first column are the times $t$ from 0 to 1, and the second column is the measurements (which in this case also happens to be between 0 and 1).

## Part A 1p
Load in the `measurements.txt` as a NumPy array and make a plot of the measurements over time.
We should be able to see that it looks a bit like the function $f(t) = t^2$, so add in the lines for $f(t) = t$ and $f(t) = t^2$ so that we can see all 3 lines in the plot.

## Part B 1.5p
We want to compare how well these measurements with with $f(t) = t^c$, but the time steps are not uniformly distributed which could make direct comparison biased towards areas with more measurements.
The goal is to obtain measurement data points that are evenly distributed from across $t$ from 0 to 1.

**Task:** Create an 1D interpolation of the data with a suitable function from `scipy`, and re-evaluate this function over 1000 uniformly distributed time steps from 0 to 1. 

## Part C 2.5p
Using the evenly spread measurement data from part B, we can compare without worrying about *bias* towards any region. We can do so by simply taking the norm of the differences of the measurements from our guess $f(t) = t^c$. 

Loop over a few values for $c$ from $1$ up to $2$ (perhaps around 10 values is sufficient), and compare $f(t) = t^c$ with the interpolated measurements and print out the error for each value of $c$.
We can define an appropriate error as the `norm` divided by $N$:
$$
\text{error} = \frac{1}{N} \sqrt{\sum_i^N (t_i^c - y_i)^2}
$$
where $N$ is the number of time points we have and $y_i$ are the interpolated values from part B.
As $N$ is can be quite large, make sure to use a vectorized NumPy expression to compute the error without additional looping.

Find (by code) the $c$ which gave the lowest error, and make another plot where you show the best fit $f(t) = t^c$ along with the measurements to see how close it gets.

# Question 3: Intervals (6p)

Similar to vectors and complex numbers, there exists other useful numerical types, like an `Interval` which represents the set of numbers between a given `low` and `high` limit.
We may use such a numeric type in our code to represent quantities which we have error bars on our measurements, for example:

> A thrown ball has a estimated velocity between $10$ and $11$ m/s, and it travels for between $5$ and $5.5$ seconds. How far will could it travel?
> With the given estimates it will be at least $10\times 5 = 50$ m and at most $11\times 5.5 = 60.5$ m.

or in code: `Interval(10,11) * Interval(5, 5.5) == Interval(50, 60.5)`

When doing maths on intervals we can think of it as computing every possible value and compute the spread of the output; what is the lowest and highest values you can obtain.
Just like multiplication above we can do the same for addition, subtraction, etc., and we end up with a very powerful tool allowing us to keep track of the accuracy of our computations!

## Part A (1p)

Write a class `Interval` which a constructor that takes a `low` and `high` value.
This object represents all the numbers between `low` and `high` (inclusive), so make sure the input makes sense; raise an appropriate builtin exception if `high` is smaller than `low` with an informative message.

## Part B (0.5p)

Add support for `repr` to make our custom type more convenient when debugging or printing (see examples).

## Part C (0.5p)

Add a method `overlaps` that takes another interval and returns true if they have any overlap (otherwise false).

## Part D (0.5p)

Add support for converting the `Interval` to a `float`, returning the mean value.

## Part E (2p)

Implement support for the common operators: negation ($-x$), addition ($x+y$), and subtraction ($x-y$).
The output should be a new `Interval` with the correct `low` and `high` values.

We should think of the operations as; *What are the range of numbers that could appear if I combine any values in the intervals from $x$ and $y$?*

1. Addition is simple; the `low` and `high` values simply add up respectively to form the new interval (no need to handle negative numbers differently).
2. When we negate an interval it changes signs, as well as the high and low switch places `-Interval(-3, 10) == Interval(-10, 3)`
3. Subtraction is like a combination of negation and addition $x-y = x+(-y)$. 

## Part F (1.5p)

Implement support for multiplication between intervals: $x*y$.

This can get *a bit* tricky when negative numbers appear. What is the `low`est and `high`est numbers you can construct from the interval $x$ and $y$? There are only 4 possible extremes!

# Question 4: Generator vectors (8p)

You must solve this problem without using `numpy` or `scipy`.

Sometimes we need to create very large arrays in memory constrained environments.
One technique that is sometimes applicable is to lazily evaluate the contents of the array as it is accessed.
The point of these as that they don't allocate memory up front, at the cost of having to re-compute the value every time we access it.

*For testing purposes the examples are using very small arrays, but your code should be able to scale up to vectors with billions of elements without using more memory.*

## Part B (2p)
