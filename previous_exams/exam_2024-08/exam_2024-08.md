Question 1: INI files (7p)
============================

INI-files are commonly used for program configurations. They use simple text based formats with support for sections.

1. Empty lines, as well as lines with only whitespace, are ignored.

2. Lines with '#' as the first non-whitespace character are comments (ignored)

3. Any line starting with '[' denotes a section, e.g. `[Graphics]`

4. Parameters and values are stored as `Parameter=Value`

Open `default_config.ini` in PyCharm to see what a typical file looks like.

While there are specialised libraries for reading and writing this type of file, we want you to write the code yourself for this assignment.

Part A (2.5p)
-------------

Write the function `read_ini` that takes a filename and returns the configuration as a dictionary:

```python
>>> config = read_ini('default_config.ini')
>>> print(config)
{'GamePlay': {'difficulty': 'medium', 'lives': '9', 'aim_assist': 'off'},
'Graphics': {'resolution': '1920x1080', 'texture_quality': 'high', 'geometry_detail': 'medium'},
'Sound': {'music': 'off', 'effects': 'on', 'volume': '100'}}
```

Raise a `ValueError` if an option is specified before any category.

Part B (2p)
-----------

Write the function `write_ini` that takes a filename and a dictionary (like the one you read in section one) and writes an ini file.
There should be one empty line between sections.


```python

                    'Gameplay': {'difficulty': 'medium', 'lives': '9'}}
```

should result in a valid ini file, like:

Question 2: Interpolating and fitting (5p)
==========================================

We have made an experiment and data has been collected in a simple text file `measurements.txt`.
The first column are the times $t$ from 0 to 1, and the second column is the measurements (which in this case also happens to be between 0 and 1).

## Part A 1p
Load in the `measurements.txt` as a NumPy array and make a plot of the measurements over time.
We should be able to see that it looks a bit like the function $f(t) = t^2$, so add in the lines for $f(t) = t$ and $f(t) = t^2$ so that we can see all 3 lines in the plot.

## Part B 1.5p
We want to compare how well these measurements with with $f(t) = t^c$, but the time steps are not uniformly distributed which could make direct comparison biased towards areas with more measurements.
The goal is to obtain measurement data points that are evenly distributed from across $t$ from 0 to 1.

**Task:** Create an 1D interpolation of the data with a suitable function from `scipy`, and re-evaluate this function over 1000 uniformly distributed time steps from 0 to 1. 

## Part C 2.5p
Using the evenly spread measurement data from part B, we can compare without worrying about *bias* towards any region. We can do so by simply taking the norm of the differences of the measurements from our guess $f(t) = t^c$. 

Loop over a few values for $c$ from $1$ up to $2$ (perhaps around 10 values is sufficient), and compare $f(t) = t^c$ with the interpolated measurements and print out the error for each value of $c$.
We can define an appropriate error as the `norm` divided by $N$:
$$
\text{error} = \frac{1}{N} \sqrt{\sum_i^N (t_i^c - y_i)^2}
$$
where $N$ is the number of time points we have and $y_i$ are the interpolated values from part B.
As $N$ is can be quite large, make sure to use a vectorized NumPy expression to compute the error without additional looping.

Find (by code) the $c$ which gave the lowest error, and make another plot where you show the best fit $f(t) = t^c$ along with the measurements to see how close it gets.

Question 3: ComplexNumber (5p total)
====================================

In this task you **should not** use any **built-in** complex number functionality, nor anything from NumPy!

# A complex numbers library

A complex number (written in Cartesian form) is a number $z = a + bi$ where $a$ is the real part, $b$ is the imaginary part and $i^2 = -1$. Binary operations are defined by e.g.

$$
\begin{aligned}
(a + bi) + (c + di) &= (a + c) + (b + d)i \\
(a + bi) * (c + di) &= (a * c - b * d) + (a * d + b * c)i \\
\end{aligned}
$$

The absolute value is defined as $|a + bi| = \sqrt{a^2 + b^2}$. A complex number can also be written on polar form as $z = (r, \theta)$ where $r = |z|$ and $\theta = \arctan(b / a)$ (in the correct quadrant). Converting from polar form to Cartesian form is done with $a = r \cos(\theta)$ and $b = r \sin(\theta)$.

The complex module
-------------------------

In this task you will create a module suitable for doing some simple operations with complex numbers.
The name of the module should be `complex`. It should contain the following:


# Part A (1p)

* A `class` named `Complex` which is used to create complex numbers:
    * Constructor such that `Complex(a, b)` creates the complex number `a + bi` and `Complex(a)` should create the complex number `a + 0im`.
    * Pretty string conversion: Numbers should be printed as:
         * `print(Complex(2, 3))` --- `2 + 3im`
         * `print(Complex(2))` --- `2 + 0im`
         * `print(Complex(2, -3))` --- `2 - 3im`
* A global variable `im` defined as $1i$.

# Part B (1p)
* Binary operations between `Complex` numbers. You only have to implement `+` and `*`. These functions should also work if one of the numbers is a real number as in `5 + Complex(3, 2)`.

# Part C (1p)
* Methods `real` and `imag` returning the real and imaginary component, respectively.
* Absolute value (by implementing the `__abs__(self)` method)

# Part D (1p)
* A method `topolar` converting the complex number to a tuple `(r, theta)`. Hint, look at `math.atan2`.
* A static method `frompolar(r, theta)` that returns an instance of `Complex`.

# Part E (1p)
* If `<` or `>` is used, an `UnorderedException` should be thrown, telling the user that complex numbers are unordered (can not be compared with e.g. `<`).
* `==` between two `Complex` numbers

Question 4: Text user interface (7p)
======================================

Similar to GUI widgets, one can quite easily create Text User Interfaces (TUI) as well.
We can borrow the concept of a "Widget" from GUIs and create a small hierarchy of text widgets.

Part A (1p)
---------------
Create an abstract base class `TUIWidget` that stores the number of `columns` and `rows` of a text widget.

It should have a abstract method `render` that takes no arguments and returns a list of rendered strings (one for each row).
Also add a (normal) method `show` that simply prints out the rendered lines.

Part B (1p)
-----------
Implement a subclass, `ProgressBar`, that only takes the number of columns, and an optional `progress` value with a default of zero.
(The ProgressBar always has a height of 1).

Also add a method `set_progress` for updating the progress.

Implement rendering of strings by showing a row filling up with `#`  proportional to the progress made, delimited by brackets, e.g with progress at 0.5:

```text
[##########          ]
```

Part C (2p)
------------
Implement another subclass, `TextField`, that takes the number of columns and rows, and an optional string (empty by default).
When rendering, it should wrap the text around the given number of columns up until the number of rows.
If the text isn't long enough, it should pad out the rows with empty lines.
If the text is to long, the overflowing characters can simply be discarded.

Also add a method `set_text` for updating the text.

Part D (2p)
-----------
Implement yet another subclass, `Box`, that takes a reference to another widget and adds a nice border around it.


```text
+--------------+
|Another widget|
|inside        |
+--------------+
```

Part E (1p)
-----------
Implement a subclass to `Box`, `GroupBox`, that still takes a widget but also a `name` as a string.
It should reuse what `Box` already renders, only replacing the top section with a name inside brackets:

```text
+-[Example]----+
|Another widget|
|inside        |
+--------------+
```
